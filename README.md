## 本地开发

发布闭环改造（源码阶段，尚未打包/安装）：先用正常官方页面完成仅上传的人工对照，再确定一个平台的实际媒体处理、封面、提交与结果回读契约。不再把可访问性树当作完整 DOM，也不根据其省略包装层的现象反推页面真实结构；没有观察到真实作品卡片结构前，不猜测视频号/B站结果选择器。2026-10-17只读查看视频号本人作品列表，当前为3条旧视频，未观察到本次测试作品；返回空编辑器，未点击最终发表。

本轮源码将官方上传/转码提示、视频交付、视频/封面解码、编辑器与提交按钮分别记录为类型化观测。缺少已解码封面仅表示识别证据不足，不再自动冒充官方处理中；该状态有独立90秒识别等待上限，保留真正上传/处理的总时限、两次新鲜就绪检查及不重复交付文件的保护。提交成功仍必须来自官方结果，观测不等于回执。

媒体观测由主进程在账号归属校验后保存，只包含状态枚举、计数和时间，排除文案、路径、HTML、Cookie、令牌与媒体URL；读取按登录用户、任务与尝试隔离。每次尝试保留首样本及最近95个转变/30秒心跳，整体最多2000条，不删除业务任务记录。详情支持只读查看，原记录重发清除旧尝试的当前观测，不复制记录、不恢复已删除记录。持久化失败明确提示，不因为日志失败重复上传。

新增真实静音 WebM 生成、原生文件交付、隐藏 WebView2 解码和从视频帧生成封面的测试，和旧的无效文件控件测试分别标注。它能验证本地媒体链路，不能证明视频号官网的实际上传/转码或真实发表。隔离回归仍须全部通过，包验证与真实发布结果单独验收；本轮尚未安装，也没有提交新作品。

2026-10-17人工对照续报：本人在保留的视频号官方发布页手动上传原素材后，正常 Windows 可访问性及矩效单窗口截图均已看到视频预览、竖封面和“编辑”。图像控件明确报告 `vertical-img-size cover-img-vertical`，所属标题栏为 `vertical-cover-wrap img-popover-wrap`；不把可访问性树省略的其他包装层当作实际 DOM 不存在的证据。此结果排除了“当前官方页面连手动上传也一直失败”，但尚不能单凭一次对照断定全部自动化故障的唯一根因。

视频号文件交付改为已观察到的官方上传按钮 → 原生文件选择事件 → 唯一主文档空视频输入框，不再仅从隐藏输入框数量/几何推测主上传器。增加来源、数量、既有素材、按钮遮挡、重复控件和重复交付保护；退出时关闭选择拦截，导航后仅允许无副作用的关闭清理，不允许跨页继续交付。原生私有管道只转发文件选择事件的文档标识、节点标识与模式，不转发路径、其他协议事件、页面脚本或凭据；渲染层没有新增任意 DOM/脚本入口。事件接收机制使用[WebView2正式事件接口](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2devtoolsprotocoleventreceiver?view=webview2-dotnet-1.0.3912.50)，并核对本机相同版本SDK声明。

新增带备用隐藏视频输入框、且必须先点击上传按钮才能启用处理器的原生样本：旧路径在真实 WebView2 控件交付测试中确实失败，新路径确认只点击一次官方入口，备用框保持空、已有素材不重复交付；真实静音视频解码/帧封面测试使用同一路径。它是针对自动化路径差异的改进，仍不是当前账号自动上传/发表已验收的证据。用户已上传的官方编辑器保留，不自动刷新、重复上传、发表或重启安装。

2026-10-17发布流程补修（仅当前源码）：单条和批量发布在创建任何任务之前统一收集各平台/账号/作品的标题、文案长度、话题、定时时间、转载来源和素材配置问题，并通过只读主进程校验确认本地素材及封面引用仍有效。错误留在编辑页集中显示、聚焦提示，不进入任务记录；草稿仍允许内容未补全。校验有并发与超时限制，离开页面或切换用户后迟到结果不能创建任务。导入、选择及恢复素材统一保留最多256个引用，避免正常批量超过32条后被后续封面选择挤掉。

已接纳任务改为严格串行阶段：交付文件一次 → 等待真实上传/媒体处理完成的两次新鲜观测 → 填写标题、简介和可见范围 → 确认封面 → 检查官方表单 → 最终确认与提交。上传100%但仍转码时不提前填表；平台未提供百分比时显示等待原因、不编造百分比，百分比控件消失后不继续显示旧数值。任务行直接展示阶段说明或具体错误，详情按本次实际完成情况显示步骤；历史记录不补造完成标记。网络、登录、动态分区等只有运行时才能获知的官方错误仍在原任务记录显示，不声称能在本地预先获知全部平台限制。完成源码回归不代表已安装或真实发布成功。

后续补修：本地素材检查增加整批30秒上限、可见的真实检查组数和取消按钮；取消、离页或切换用户后，迟到结果不能创建任务，原文案与素材保留。空文件在本地拦截；封面错误保留具体原因。单账号提交前检查异常不再连带其他已准备账号失败，零个按钮与多个按钮分别提示，封面就绪等待也归属封面阶段。相同进度继续轮询，但不重复触发整份任务列表渲染、时间更新和存档。

### RC29 开发中：视频号原生发布链路

修复原生 Edge 已绑定但发布队列仍被 Electron 专用接口阻止的问题。原生页面由主进程校验矩效用户、绑定账号、独立会话、官方域名和本人昵称后，接入同一套上传、填表、进度、封面、核对、提交及原生回执。后台 WebView2 页面隐藏运行并保留正常布局，不覆盖账号管理、评论或私信的前台编辑器；前台已有未保存发布表单时不强行覆盖。仅视频工作流接入本轮代码，图文入口未核验时拒绝把图片错传成视频封面。

### RC12 增量与验收边界

以下为 RC11 保留能力：

单条视频、批量视频和批量图文共用账号选择弹窗：按分组、标签、平台或常用列表选择，支持搜索、组内选择、已选移除、取消和确定。列表及配置记忆按矩效用户隔离保存在本机；记忆仅包含平台选项，不包含文案、素材、封面句柄和发布时间。

抖音、小红书、B站的字段参考用户提供的界面；视频号补充短标题、描述、话题、位置、合集、活动、链接、商品、声明、互动权限及时间配置。字段出现不代表当前账号具备该能力，平台可能因作品类型、地区、版本和权限显示不同项目。当前配置长度上限用于提交前提示，不会静默截断文案。

自动同步边界：

- 标题、简介、可见范围、分类和创作类型：仅在官方编辑器唯一识别到对应控件、匹配到有效选项后填入。
