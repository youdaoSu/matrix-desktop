# RC264 系统迭代：回执查询与后台补读

## 本轮范围

本轮在已实际完成第二十八天自动投稿的 RC263 上继续迭代，不重新发表该作品，不改写其成功回执，不自动启用新的评论、私信、删除任务。

### 已实现的候选改动

- 原生回执日志查询拆为独立模块。冷查询按 64 KiB 流式读取；重复查询使用最多 16 项、序列化总量 4 MiB 的 LRU 缓存，单项超过 1 MiB 不缓存。
- 每次查询仍检查文件标识、大小和纳秒修改/变更时间。应用内写入立即失效；外部追加、文件替换、截断或重建后重新读取。查询期间文件变化不缓存该次结果。
- 返回值与缓存隔离，账号所有权过滤、完整历史查找、最近 200 条展示和最近 80 条追踪约束保持。缓存不是投稿成功证据，也不截断业务日志。
- 作品编号补读仍只读，最多同时两个账号、同账号串行、每轮最多三次；等待间隔从固定值改为 15 秒、30 秒退避。
- 保留已完成/冲突的结束标记，防止旧刷新重复启动；收到明确失败、完整编号或冲突的新结果时，忽略先前在途结果。账号绑定变化后旧结果不能再回写前端。
- 会话补读记录最多 512 项；仅淘汰结束或已耗尽的记录，不挤掉正在执行的任务。持久回执仍为最终依据，重启后不是永久免查。

## 验证边界

首轮 10,000 条合成记录测试：三个冷查询约 135 ms，随后 300 次不变查询约 34 ms，内容读取次数为 0。测量受本机负载影响，不代表整个软件速度提升倍数。首次读取和日志变更后的冷查询仍同步执行，本轮没有把所有磁盘 I/O 移出主进程。

专项覆盖：文件追加、其他写入实例、截断、同尺寸替换、UTF-8 边界、半条记录续写、缓存结果隔离、跨用户过滤、历史上限、LRU 淘汰；补读覆盖旧回执重入、在途结果晚到、绑定变化和停止后的隔离。完整回归、安装包核验和实际安装各以本轮独立报告为准，不从专项通过推断全部交付。

## 系统盘点：仍不能声称“全部自动化”

现有实现清单的权威入口为 `shared/feature-delivery.ts`，界面“功能与数据来源”继续按真实状态显示：

1. 已接入的视频发布、缓存采集、账号隔离和本机队列继续保留明确授权、防重发及账号身份核对。
2. 粉丝仅能保证官网可访问范围；人数差异不能当作已采集全量，首次采集不能当关注时间。
3. 部分平台图文、全平台违规事件、同一作品多时点播放快照仍缺适配或官方来源。
4. 旧回复规则与账号运营配置尚未自动迁移，不擅自开启发送。
5. 作品置顶、删除前作、删除源文件等未接通控件仍不能执行，更不能仅改本地状态表示成功。
6. 官网登录、验证码和授权限制需要本人处理；本机定时不等于关机后云端调度。

后续优先级：继续缩短真实投稿后的结果识别等待；逐项补齐可验证的功能闭环；将冷查询和大历史加载进一步异步化。任何真实发布/删除/发送测试都需明确目标，不因“系统迭代”而生成额外作品或消息。
