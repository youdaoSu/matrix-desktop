RC304 background heartbeat candidate — 2026-10-31

Problem and change
RC303 fixed hidden-window liveness by holding a native background-throttling
lease. The lease also kept unrelated main-renderer timers awake. RC304 adds a
scoped main-process heartbeat notification and retains renderer timers as a
fallback. Successful main-event configuration restores the prior throttling;
legacy clients retain the existing lease. The requester reuses the five-second
host scheduler, uses monotonic time and weak ownership, and rate-limits each
workspace. Notifications contain only the workspace ID and never extend native
authorization. Actual authenticated responses are still required within45s.

The real preload removes listeners by their original function, omits native
event objects, and validates the payload. The React runtime ignores obsolete
workspaces, coalesces triggers, retries configuration after errors and disposes
subscriptions. No markup, style, platform request rate or business schema change.
Source comparison with frozen RC303 found only the non-rendering runtime and
its type declaration changed among198 frontend files.
