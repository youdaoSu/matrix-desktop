# RC323：审核复查、作品编号与运行时（已安装验证）

RC323 已在本机安装并验证启动。RC322 的源码回归通过，但包内后台绘制恢复失败，因此未交付；原失败记录保留。RC323 包含评论入口迁移、内存清理和以下修复。

## 审核结果自动更新

- 已受理且待审核的作品，不再以“配置了追评”作为自动复查的前提。
- 同一用户会话内，最多安排六次间隔复查：15、30、60、120、300、600 秒；间隔从上次检查完成开始计算，并非对平台审核时长的承诺。两条全局并发上限保留。
- 启动恢复最近七天的原待审核回执；优先按本次受理时间计算，避免较早建立、最近才重试的任务被遗漏。
- 未知结果的一次检查不会拦住后来到达的正式受理事件。重复回执通知、检查中的刷新不会补充次数或并发重复检查。
- 审核通过/未通过后停止自动检查；身份、登录或无法识别的读取失败暂停自动检查，原受理事实保留。不会重新上传或点击发布。

## 发布后作品编号与评论入口

- 审核通过后将结果送入独立作品编号读取队列。若审核中已经耗尽最初三次读取，允许新一轮有限读取；重复通知或旧快照不能不断重置次数。
- 评论管理的单条评论入口在原发布回执缺少作品编号时，提供“重新读取作品编号（不发送）”。核对原回执、账号与作品后才展示正文预览；保留原账号归属及发送确认检查。
- 迁移后的入口为作品所属账号发送一条经人工预览确认的评论。本轮不执行真实评论或私信，不恢复旧多账号轮发入口。

## 运行时与验证范围

- Electron 从 33.4.11 更新到固定 44.7.2。原版本在真实隔离窗口暂停/恢复后间歇出现 RAF 不恢复；44.7.2 包含相关上游修复，首次对照和连续五轮隔离测试通过，页面 DOM、滚动位置、游标保持，窗口未显示。
- 官方变更参考：[后台节流恢复修复](https://releases.electronjs.org/pr/54311)。升级验收仍须完整回归和实际安装包检查，不能以单项通过替代。
- 构建脚本从项目清单读取固定运行时版本，并检查已有工具目录的版本，防止新源码继续使用旧运行时。
- 审核调度、作品编号恢复、真实 React 评论恢复入口专项与客户端类型检查通过；完整 246 组源码回归及 97 组实际包检查通过。没有证明长期运行完全无泄漏。

失败记录保留：RC322 首轮编译输出被 PowerShell 当成错误、包内后台动画恢复失败；隔离的缩放/重绘/延迟重试等探针未稳定解决，不并入产品。新运行时验证不能倒推 RC322 包通过。

运行时迁移中的测试适配也保留原失败：窄屏用精确 440 CSS 像素模拟以排除 Windows 分数缩放；声明控件测试等待首帧命中区域建立后发送原可信点击；头像测试允许已解码图片复用，同时断言新会话确实重新挂载、失败重试上限不变。没有放开产品的遮挡、身份或发送检查。

协议模拟与 webRequest 组合在新运行时中出现“最终 JSON / 初始 302 状态”不一致，独立普通本机 HTTP 重定向则正确返回 200。摘要夹具改用本机回环 302→200 的真实响应，另验原始 302 仍拒绝、尾斜杠地址仍正常关联，245 项通过。该夹具没有连接真实平台；此对照不代表所有真实站点的重定向都已经端到端验证。
