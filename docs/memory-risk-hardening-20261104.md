# 互动模块内存风险修复候选（2026-11-04）

本轮只修改源码；已安装 RC321 未替换。RC322 既有评论入口迁移及其他未提交改动保留。此前候选源摘要不再适用于本轮修改后的源码。

## 修复

- 账号移除、原生身份或会话改变时，从评论/粉丝的 entries、hydrated、刷新请求、调度时间和轮转记录中移除失效键。普通页面切换保持同账号缓存及分页断点。
- 在途请求继续持有原调度占位直到自身 finally 释放，避免清理时并发重入。旧代请求不能回填新会话，卸载后拒绝迟到的操作回执更新。
- Provider 卸载释放缓存、请求集合和调度引用；原有定时器、事件监听释放继续保留。
- 图片预览队列支持 AbortSignal，私信图片及评论/粉丝图片在卸载时立即移除尚未执行的闭包、解除 abort 监听；已执行 IPC 不假称已取消，仍沿用原结果隔离检查。并发上限 2、等待上限 256 不变。同步抛错和 Promise 拒绝均释放队列槽位。
- 名单容量统计逐条编码，避免整表 JSON 字符串及其 UTF-8 副本同时驻留；合并行索引不再创建整表键值元组数组。增量大小包含 JSON 分隔逗号，保持和整表 UTF-8 字节数一致。
- 记录载荷单份 32 MiB、总计 128 MiB 的提交前预算，超过时暂停继续载入、保留旧缓存和本地存档。此预算是序列化记录大小，**不是整个应用或 JavaScript 堆内存上限**。没有删除数据库、草稿、账号资料或分页存档。
